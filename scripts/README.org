#+TITLE: scripts/ -- Data pipeline
#+OPTIONS: toc:1

The whole pipeline lives in =scripts/pipeline.clj=.

* Single format: subdomains.csv

The pipeline operates on one file per domain,
=countries/<c>/sources/roots/<d>/subdomains.csv=, with header
=subdomain,http_status=.
Status is empty after =fetch= / =normalize=, filled by =probe=, and
preserved by later phases.

* Commands

** Aggregated phases

Available both as =bb pipeline <cmd>= (via =bb.edn=) and as =bb
scripts/pipeline.clj <cmd>=:

#+begin_src bash
  bb pipeline collect            # crt.sh -> probe -> 200
  bb pipeline enrich             # wikidata + 4 parallel sources
  bb pipeline report             # candidates.csv + summary.md
  bb pipeline all                # everything in sequence

  bb pipeline report FRA_france  # restrict to one country
  FORCE=1 bb pipeline enrich     # force-overwrite outputs
#+end_src

** Targeted phases

#+begin_src bash
  bb scripts/pipeline.clj fetch gov.it gouv.fr  # crt.sh on specific domains
  bb scripts/pipeline.clj retry                 # replay FAILs from last log
  bb scripts/pipeline.clj normalize             # clean every CSV
  bb scripts/pipeline.clj probe gov.it          # HTTPS HEAD probe
  bb scripts/pipeline.clj mx gov.it             # DNS MX lookup -> mx.csv (email signal)
  bb scripts/pipeline.clj aggregate             # rebuild public-sector.csv
  bb scripts/pipeline.clj central               # extract public-sector-central-gov.csv
  bb scripts/pipeline.clj cisa                  # refresh US federal .gov registry (CISA)
  bb scripts/pipeline.clj lannuaire             # refresh FR central-admin registry (service-public)

  bb scripts/pipeline.clj wikidata Q142:FRA_france
  bb scripts/pipeline.clj iana FRA_france
  bb scripts/pipeline.clj cia FRA_france
  bb scripts/pipeline.clj un-desa FRA_france
  bb scripts/pipeline.clj oecd FRA_france
  bb scripts/pipeline.clj meta FRA_france
  bb scripts/pipeline.clj cross-check FRA_france

  bb scripts/pipeline.clj build-qid             # rebuild data/country_qid.csv
  bb scripts/pipeline.clj validate-un           # check un_status against the official UN member list
  bb scripts/pipeline.clj forges                # forge-looking hosts -> data/forge-candidates.csv
  bb scripts/pipeline.clj forges-swh            # forge targets unknown to SWH -> data/forge-unknown-swh.csv
  bb scripts/pipeline.clj github-orgs           # GitHub governments.yml -> data/github-gov-orgs.csv
  bb scripts/pipeline.clj regex                 # email-domain regexes -> data/domain-regexes.csv
#+end_src

=forges-swh= checks forge targets against the Software Heritage
origin-search API and keeps those the archive does not know yet.
Targets are the harvested hosts of =data/forge-candidates.csv= plus
the curated entries of =data/known-forges.csv= (seeded from the
[[https://gitlab.softwareheritage.org/swh/products/insights/swh-sopc-data-sources][swh-sopc-data-sources]] catalog list) whose =kind= is =forge= or
=github-org= -- =catalog= entries only point at code hosted elsewhere,
so they are listed for reference but not searched. With the
=github-orgs= argument, the organizations of
=data/github-gov-orgs.csv= (from GitHub's community-maintained
=governments.yml=, fetched by =bb pipeline github-orgs=) are checked
too. The anonymous API allows 10 requests per rate-limit window (the
command paces itself accordingly); set =SWH_TOKEN= to authenticate and
go faster -- recommended for the ~1000-org =github-orgs= sweep.

=regex= derives, from the confirmed central-government roots, one
email-domain regex per country (=data/domain-regexes.csv=) plus a
global one (=data/domain-regex-all.txt=), in the =domain_regex= format
expected by [[https://gitlab.softwareheritage.org/swh/products/insights/swh-institutional-analysis][swh-institutional-analysis]]:
=.*@(.*\.)?(?:gouv\.fr|insee\.fr|…)$=.

* Prerequisites

- =babashka= (1.12+) -- HTTP via the bundled =babashka.http-client=, no
  external tool needed
- =data/world-governments.csv= (master list with =un_status= column)
- =data/country_qid.csv= (Wikidata mapping, built via =bb pipeline build-qid=)
- =data/factbook_aliases.csv= and =data/un_desa_aliases.csv= (country-name overrides)
- =countries/<ISO3>_<slug>/sources/roots/<domain>/= directories initialized

* Environment variables

| Var      | Effect                                          | Default |
|----------+-------------------------------------------------+---------|
| =FORCE=     | overwrite existing outputs                      | =0=       |
| =PARALLEL=  | concurrent requests (fetch / probe)             | varies  |
| =TIMEOUT=   | HTTPS request timeout (probe), seconds          | =5=       |
| =SWH_TOKEN= | SWH API bearer token (=forges-swh=)               | unset   |

* Scoring (cross-check)

For each uncovered candidate hostname:

| Criterion                                                  | Points |
|------------------------------------------------------------+--------|
| UN/DESA-declared national portal                           |     +5 |
| Per distinct Wikidata mention (capped at +6 = 2 mentions)  |     +3 |
| Hostname listed in the curated source channel (manual)     |     +3 |
| Hostname under the country's primary ccTLD                 |     +1 |
| Central pattern (=gov./bund./gouv./governo./gobierno./…=)    |     +1 |
| Wikidata label contains a Factbook institution name        |     +2 |
| Label suggests a territorial subdivision (Land, region, …) |     -5 |
| 3+ Wikidata mentions, none with =federal/national/sovereign= |     -5 |

Score clamped to =[0, 10]=. The two penalties only apply when ranking
central candidates -- =candidates-local.csv= has its own ranking where
burying subnational entries would defeat the purpose.

Output: two files with columns =hostname,score,sources,label,level=:

- =countries/<c>/candidates.csv= -- central-administration candidates
  (=level= is =central=, or blank when nothing is known yet), sorted
  score desc / hostname asc;
- =countries/<c>/candidates-local.csv= -- candidates attributed to a
  subnational administration: =level=central-1= for bodies of a
  first-level subdivision of the country (Land, state, region,
  province…), =level=local= for anything below (city, county,
  department…). =central-1= rows sort first, then score desc /
  hostname asc.

The =level= comes from the Wikidata P1001 jurisdiction captured at
fetch time (the country itself ⇒ =central=, one of its first-level
subdivisions ⇒ =central-1=, anything else ⇒ =local=), from the
optional =level= column of the curated source (which wins), or from
label patterns as a fallback: the subdivision vocabulary pattern marks
a host =local=, upgraded to =central-1= when its label names one of
the country's first-level subdivisions. Those subdivisions (the
country's Wikidata P150 values, dissolved ones excluded) are fetched
during the =wikidata= phase into
=countries/<c>/sources/wikidata/subdivisions_level1.csv= -- also under
=FORCE=1= refetch semantics. Blank levels are consolidated over time
as sources are refetched or curated.

The =central-1= tier exists so downstream reports (e.g. /State of
Public Code/) can widen their scope from the central administration to
central + first subdivision level without pulling in the long tail of
municipal domains.

* Curated candidates (manual)

Central-government domains the automated harvest (Wikidata / UN-DESA)
misses can be added by hand in an isolated, versioned source:

=countries/<c>/sources/curated/central_admin.csv= -- schema
=type,label,website,hostname,provenance[,level]=. The =report= phase
reads it alongside Wikidata and UN/DESA, so listed hosts re-enter
=candidates.csv= reproducibly, scored =+3= and tagged =sources=curated=.
The optional =level= column (=central= / =central-1= / =local=)
overrides every other level signal -- this is where manual
consolidation happens.
The =provenance= column records where each entry came from. The
directory is excluded from root-domain promotion (it is part of
=source-dirs-set=), so adding a candidate here never auto-promotes it.

* Manual curation workflow

To promote a candidate into the dataset:

#+begin_src bash
# 1. Inspect the scored candidates
less countries/ITA_italy/candidates.csv

# 2. If legit, create the root directory (under sources/roots/)
mkdir -p countries/ITA_italy/sources/roots/quirinale.it

# 3. Run the standard pipeline on that domain
bb scripts/pipeline.clj fetch quirinale.it
bb scripts/pipeline.clj normalize
bb scripts/pipeline.clj probe quirinale.it
bb scripts/pipeline.clj aggregate

# 4. Confirm the candidate is no longer flagged
bb scripts/pipeline.clj report ITA_italy
#+end_src

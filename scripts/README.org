#+TITLE: scripts/ -- Data pipeline
#+OPTIONS: toc:1

The pipeline lives in =scripts/=, five namespaces loaded through the
=:paths= of =bb.edn=: =common= (CSV and HTTP I/O, the per-country
decision files, the country-metadata tables), =enrich= (the
enrichment sources), =registries= (the official registries),
=indegree= (the link graph) and =pipeline= (harvest, aggregation,
scoring, the policy table and the dispatcher).

* Per-country layout

Two hand-edited files per country carry every decision:

- =countries/<c>/curated.csv= (=domain,level,name=) -- the confirmed
  domains, =level= =central=, =central-1= or =local=. A =local= row is
  a lower-tier label of a shared root (=abingdon.gov.uk=): it leaves
  the root's subtree in the policy table and keeps its hosts out of
  =proposed.csv=, but is never harvested.
- =countries/<c>/excluded.csv= (=domain,reason=) -- hostnames out of
  scope altogether: rejected proposals. Directly under a central root,
  an excluded label leaves the subtree like a =local= one; a domain
  listed here also leaves the registries.

Everything else is generated. The *confirmed* domains of a country
are compiled in memory at every run (=common/compile-confirmed=,
cached as =confirmed-rows=): the registry files
=sources/<registry>/registered.csv= (=domain,level=, written by
=cisa=, =lannuaire=, =govuk= and =bb directories=) plus =curated.csv=
minus =excluded.csv=; a =curated= row wins over a registered
duplicate (its level too), and a domain both curated and excluded, or
an unknown level, aborts any command with exit 1. =bb pipeline check=
runs that compilation alone and also warns about a curated row a
registry already lists. The generated files are =proposed.csv=,
=summary.md= and the =sources/= tree.

The harvest lives in one file per harvested root,
=countries/<c>/sources/crtsh/<root>.csv=, header
=subdomain,http_status,mx=, the root's own apex included. Status and
MX are empty after =fetch= / =normalize=, filled by =probe= / =mx=,
and preserved by later phases. Confirming a root and harvesting it
are two distinct steps: =fetch <root>= creates the harvest file of a
confirmed =central= or =central-1= domain (and refuses any other;
=local= rows are never harvested); a confirmed root without a harvest
only gets its apex probed, into =sources/probes/roots.csv=.

* Commands

** Aggregated phases

Available both as =bb pipeline <cmd>= (via =bb.edn=) and as =bb
scripts/pipeline.clj <cmd>=:

#+begin_src bash
  bb pipeline collect            # fetch + retry + normalize + probe + aggregate + domains
  bb pipeline enrich             # wikidata + iana + cia + un-desa + oecd + meta, in parallel
  bb pipeline report             # proposed.csv + summary.md
  bb pipeline all                # everything in sequence

  bb pipeline report FRA_france  # restrict to one country
  FORCE=1 bb pipeline enrich     # force-overwrite outputs
#+end_src

** Targeted phases

#+begin_src bash
  bb scripts/pipeline.clj fetch gov.it gouv.fr  # crt.sh on specific domains
  bb scripts/pipeline.clj retry                 # replay FAILs from last log
  bb scripts/pipeline.clj normalize             # clean every harvest file
  bb scripts/pipeline.clj probe gov.it          # HTTPS HEAD probe (no arg: + unharvested roots)
  bb scripts/pipeline.clj mx gov.it             # DNS MX lookup -> mx column (no arg: + unharvested roots)
  bb scripts/pipeline.clj probe-proposed FRA_france  # HTTPS + MX of the proposed hosts
  bb scripts/pipeline.clj aggregate             # rebuild data/public-sector-domains.csv
  bb scripts/pipeline.clj domains               # central+ scope -> data/public-sector-domains-central+-policy.csv
  bb scripts/pipeline.clj check [C…]            # the decision files compile (exit 1 on a contradiction)
  bb scripts/pipeline.clj cisa                  # CISA federal .gov list -> sources/cisa/registered.csv
  bb scripts/pipeline.clj lannuaire             # FR service-public directory -> sources/lannuaire/registered.csv
  bb scripts/pipeline.clj govuk                 # UK sub-central bodies -> sources/govuk/registered.csv

  bb scripts/pipeline.clj wikidata Q142:FRA_france
  bb scripts/pipeline.clj iana FRA_france
  bb scripts/pipeline.clj cia FRA_france
  bb scripts/pipeline.clj un-desa FRA_france
  bb scripts/pipeline.clj oecd FRA_france
  bb scripts/pipeline.clj meta FRA_france
  bb scripts/pipeline.clj cross-check FRA_france

  bb scripts/pipeline.clj build-qid             # rebuild data/country_qid.csv
  bb scripts/pipeline.clj validate-un           # check un_status against the official UN member list
#+end_src

The =iana=, =cia=, =un-desa=, =oecd= and =meta= phases fill one table
each under =data/sources/= (=iana.csv=, =cia_factbook.csv=,
=un_desa.csv=, =oecd.csv=, =country_data.csv=), one row per country
keyed by =country_dir=, holding only the fields =summary.md= and the
scoring read; a country with a row is skipped unless =FORCE=1=.

Two more side scripts share the same layout:

- =scripts/detect-from-directories.clj= (=bb directories harvest [C…]=)
  harvests the machine-readable official directories of public bodies
  (declarative =directory-specs=, one entry per country: NO, DE, IT,
  CA, NL, UK, PL). Depending on the spec's =:channel= it writes
  =sources/<registry>/registered.csv= (authoritative central scoping:
  Norway's =brreg=) or
  =sources/directory/orgs.csv= (feeding =proposed.csv= with a +4 bonus
  and the =directory= source tag).
  Unlike the two others it serves the core goal; it lives apart only
  to keep =pipeline.clj= lean.
- =scripts/detect-universities.clj= (=bb universities fetch|migrate=)
  keeps the strictly public universities as a parked dataset in
  =data/public-universities.csv=, out of the pipeline's scope.

Forge and source-code-catalog detection lives in its own script,
=scripts/detect-forges.clj= (=bb forges <command>=): it shares the
harvested data of this repository but serves the Software Heritage
catalog goal of [[https://gitlab.softwareheritage.org/swh/products/insights/swh-sopc-data-sources][swh-sopc-data-sources]], not the email-domain goal.

#+begin_src bash
  bb forges forges                              # forge-looking hosts -> data/forge-candidates.csv
  bb forges forges-swh [github-orgs]            # forge targets unknown to SWH -> data/forge-unknown-swh.csv
  bb forges forges-probe                        # re-probe forge-unknown-swh.csv (type + accessibility)
  bb forges github-orgs                         # GitHub governments.yml -> data/github-gov-orgs.csv
#+end_src

=forges-swh= checks forge targets against the Software Heritage
origin-search API and keeps those the archive does not know yet.
Targets are the harvested hosts of =data/forge-candidates.csv= plus
the curated forges of =data/known-forges.csv= (seeded from the
swh-sopc-data-sources catalog list); the source-code catalogs of
=data/known-catalogs.csv= only point at code hosted elsewhere, so they
are kept for reference but not searched. With the
=github-orgs= argument, the organizations of
=data/github-gov-orgs.csv= (from GitHub's community-maintained
=governments.yml=, fetched by =bb forges github-orgs=, plus the local
additions of =data/github-gov-orgs-extra.csv=) are checked
too. Only the origins hosted on the target (or a subdomain of it)
count as hits: the API matches URL tokens, not substrings. The
anonymous API is rate-limited (the command paces itself); set
=SWH_TOKEN= to authenticate and go faster -- recommended for the
~1000-org =github-orgs= sweep. Targets whose lookup failed stay in the
output with the note =SWH API error= instead of being dropped.

Each unknown target is then probed over HTTPS (curl =-ksL=) to record
the forge software sniffed from its homepage (=forge_type=), the final
HTTP status code (=http_status=, =000= when unreachable) and a short
diagnostic (=note=: DNS failure, timeout, WAF, default page,
cross-host redirect). =forges-probe= refreshes those three columns in
place without re-querying the SWH API.

=domains= derives, from the central+ scope (the confirmed =central=
and =central-1= domains of UN members and observers), the match
policy as a single table,
=data/public-sector-domains-central+-policy.csv=
(=domain,kind,country,level=): =subtree= is a domain and everything
below it, =exact= a domain alone (nothing below it), =exclude= a
domain and everything below it to keep out; =level= is the tier of
the row's domain (=local= on an =exclude= row, blank when it comes
from =excluded.csv=). When a host falls under several rows
(=campinas.sp.gov.br= is under =gov.br= subtree and under =sp.gov.br=
exact), the most specific one, the longest domain, decides. This is
the file downstream pipelines such as
[[https://gitlab.softwareheritage.org/swh/products/insights/swh-institutional-analysis][swh-institutional-analysis]] consume: it needs no lookaround and no
regex engine at all. Domains already covered by a root
(e.g. =fazenda.gov.br= under =gov.br=) are pruned as redundant.

A root domain falls under one of three regimes, so the table covers
central government plus the first subdivision tier and nothing below:

1. *Level-homogeneous suffix* (the default: =gouv.fr=, =gc.ca=,
   =go.jp=…): everything under the root is central government, a
   single =subtree= row is correct.
2. *Mixed suffix, structurally separable* (=gov.br=, =gov.au=): lower
   government tiers live under known labels of the root. A first-tier
   body (=sp.gov.br=, the 27 Brazilian states, the 8 Australian
   states/territories) is a =central-1= row of =curated.csv=:
   =domains= turns it into an =exact= row and takes its label out of
   the root's subtree. A lower-tier label is a =local= row
   (=abingdon.gov.uk=): =domains= turns it into an =exclude= row, out
   entirely. Anything deeper inside a =central-1= subtree only matches
   once listed explicitly in the central+ scope, so lower tiers hosted
   there stay out -- =fazenda.gov.br= and =sp.gov.br= match,
   =campinas.sp.gov.br= (a municipality) and =abingdon.gov.uk= do
   not.

   The UK is a heavier variant: councils of all tiers (incl. ~4500
   parish councils), combined authorities and devolved administrations
   sit directly under =gov.uk= next to the departments. =bb pipeline
   govuk= generates the exclusions from the official CDDO list of all
   registered gov.uk domains, classified via Wikidata GSS anchoring
   (P836 statistical-geography codes, on the entity or its P1001
   jurisdiction, country-level codes excluded) plus naming conventions
   (=…parish=, =…-pc=, =…cc=, =…-ca=, =…-ni=, fire services, national
   parks…), with a small allowlist protecting central acronym bodies
   (DECC, JNCC, RPC…). The generated list goes to
   =sources/govuk/registered.csv= (locals as =local=, devolved bodies
   as =central-1=); residual sub-central bodies with opaque names are
   curated by hand as =local= rows of =curated.csv=. Refresh with =bb
   pipeline govuk= after updating =govuk-domains-url= to the latest
   yearly snapshot.
3. *Mixed suffix, not separable by shape* (US =.gov=, where federal,
   state and city domains share the same structure): the central-level
   domains must be enumerated from an authoritative register into
   =sources/<registry>/registered.csv= (e.g. CISA's federal =.gov= list
   via =bb pipeline cisa=).

* Prerequisites

- =babashka= (1.12+) -- HTTP via the bundled =babashka.http-client=, no
  external tool needed
- =data/world-governments.csv= (master list with =un_status= column)
- =data/country_qid.csv= (Wikidata mapping, built via =bb pipeline build-qid=)
- =data/factbook_aliases.csv= and =data/un_desa_aliases.csv= (country-name overrides)
- =countries/<ISO3>_<slug>/curated.csv= listing the roots to harvest

* Environment variables

| Var      | Effect                                          | Default |
|----------+-------------------------------------------------+---------|
| =FORCE=     | overwrite existing outputs; re-probe every host (=probe=, =mx=, =probe-proposed=); refetch a country's metadata row | =0= |
| =PARALLEL=  | concurrent requests (fetch / probe)             | varies  |
| =TIMEOUT=   | HTTPS request timeout (probe), seconds          | =5=       |
| =SWH_TOKEN= | SWH API bearer token (=forges-swh=)               | unset   |
| =CONC_WIKIDATA=, =CONC_IANA=, =CONC_CIA=, =CONC_UN_DESA=, =CONC_META= | countries processed in parallel by each enrichment source | 3, 4, 8, 4, 4 |

* Scoring (cross-check)

For each uncovered candidate hostname:

| Criterion                                                  | Points |
|------------------------------------------------------------+--------|
| UN/DESA-declared national portal                           |     +5 |
| Per distinct Wikidata mention (capped at +6 = 2 mentions)  |     +3 |
| Hostname under the country's primary ccTLD                 |     +1 |
| Central pattern (=gov./bund./gouv./governo./gobierno./…=)    |     +1 |
| Wikidata label contains a Factbook institution name        |     +2 |
| Listed in the country's official directory (=bb directories=) |     +4 |
| Linked from N same-country public-sector domains (=indegree=): N >= 3, 5, 10, 20 | +3, +4, +5, +6 |
| Label suggests a territorial subdivision (Land, region, …) |     -5 |
| 3+ Wikidata mentions, none with =federal/national/sovereign= |     -5 |

Score clamped to =[0, 10]=. The two penalties only apply to hosts not
already known as subnational.

Output: =countries/<c>/proposed.csv=, columns
=hostname,score,sources,label,level,http_status,mx=, sorted score desc
/ hostname asc. =level= is =central=, =central-1= (bodies of a
first-level subdivision of the country: Land, state, region,
province…) or blank when nothing is known yet; hosts attributed to a
lower tier (city, county, department…) are not written anywhere.
Hosts covered by a confirmed domain (any country -- Wikidata files
embassies under their host country) or by an =excluded.csv= domain
are left out. The two probe columns come from
=sources/probes/proposed.csv=, filled by =bb pipeline probe-proposed=
and kept across =report= runs.

The =level= comes from the Wikidata P1001 jurisdiction captured at
fetch time (the country itself ⇒ =central=, one of its first-level
subdivisions ⇒ =central-1=, anything else ⇒ =local=), or from label
patterns as a fallback: the subdivision vocabulary pattern marks
a host =local=, upgraded to =central-1= when its label names one of
the country's first-level subdivisions. Those subdivisions (the
country's Wikidata P150 values, dissolved ones excluded) are fetched
during the =wikidata= phase into
=countries/<c>/sources/wikidata/subdivisions_level1.csv= -- also under
=FORCE=1= refetch semantics. Blank levels are consolidated over time
as sources are refetched or curated.

The =central-1= tier exists so downstream reports (e.g. /State of
Public Code/) can widen their scope from the central administration to
central + first subdivision level without pulling in the long tail of
municipal domains.

* Manual curation workflow

A decision is one line in a hand-edited file. To confirm a proposal:

#+begin_src bash
# 1. Inspect the proposals
less countries/ITA_italy/proposed.csv

# 2. If legit, add it to curated.csv (level central, central-1 or local)
echo 'quirinale.it,central,Presidency of the Republic' >> countries/ITA_italy/curated.csv
bb scripts/pipeline.clj check ITA_italy

# 3. Optionally harvest its subdomains (confirmed roots need no harvest)
bb scripts/pipeline.clj fetch quirinale.it
bb scripts/pipeline.clj normalize
bb scripts/pipeline.clj probe quirinale.it
bb scripts/pipeline.clj mx quirinale.it

# 4. Rebuild the outputs; the host is no longer proposed
bb scripts/pipeline.clj aggregate
bb scripts/pipeline.clj domains
bb scripts/pipeline.clj report ITA_italy
#+end_src

To reject one, add its hostname to =countries/ITA_italy/excluded.csv=
(=domain,reason=) and run =report=: it never comes back. Keep both
files sorted by domain, so =git diff= stays readable.
